# Focused acceptance boundaries

Each row names a current test module, what it proves and what it does not prove. A row is a boundary that task cards select, not a recorded pass.

| Module | Proves | Does not prove |
|---|---|---|
| `tests.test_cli_protocol` | Actual subprocess argv/JSON/stderr/exit behavior, deterministic capabilities | Model reasoning or host skill discovery |
| `tests.test_manifest_registry` | Prospective edits, no-op bytes, explicit roots, registry lifecycle | Cross-machine state convergence |
| `tests.test_skill_catalog` | Flat package validation and passive inspection | Arbitrary YAML or script trustworthiness |
| `tests.test_reconcile_plan` | Ownership truth table, source/path checks, stale-plan fingerprint | Atomic multi-file application |
| `tests.test_reconcile_apply` | Actual symlinks, safe unlink, parent/type drift, journaled apply | Race-proof hostile same-user filesystem containment |
| `tests.test_recovery` | Restart after interruption, complete/rollback/refusal without user-data overwrite | Git checkout rollback or power-loss durability on all filesystems |
| `tests.test_subprocess_policy` | Bounded helper processes, no prompt, timeout cleanup, sanitized JSON | Control of arbitrary user Git helpers/filters |
| `tests.test_launcher` | Native launcher quoting, argument forwarding, exit propagation | Installation through package managers |
| `tests.test_end_to_end` | Full direct CLI workflow on fixtures and shared context cutover | Successful native results on an OS not exercised |
| `tests.test_public_baseline` | Public human/`--json`/raw invocations from unprepared starting states; the RFC-MASK-0018/0019 baseline cases, with no `expectedFailure` decorator left | Native terminal prompts, host role loading, the real AgentSkills package |
| `tests.test_readme_journeys` | The README's recipes, beginning with `tap add`, replayed as written through the installed launcher and the plain entrypoint on a local fixture tap, including terminal prompts on a POSIX pseudoterminal | Native Windows console prompts (recorded separately), host role loading, a network remote, `self update` against a live remote |
| `tests.test_tap_bootstrap` | On an empty MASK_HOME with no working checkout on disk, `tap add` then `install` over a local bare upstream writes v3 config, a bare cache, a v2 declaration and lock, and store-targeted links. An offline install before any fetch refuses, naming the tap, and writes nothing. `init` writes an empty catalog and refuses its retired source option. Legacy records on a tap catalog refuse `migration.required` | A network remote or authentication, the real AgentSkills package, native results on an OS not exercised |
| `tests.test_update` | With two local `file` taps and three consumers, `update` fetches each referenced tap once (counted from Git trace2 events) and activates one journal. An unreachable tap blocks only its consumers (`update.incomplete`). `--dry-run`, `--offline` and `--expect-plan-hash` never fetch. A moved tag refuses without `--allow-ref-rebind`. Dev-link consumers are skipped, or refused when scoped. `source fetch` without a name deploys nothing. Git hooks are suppressed, bad candidates refuse typed and a late failure rolls back to exact bytes | Network transports or authentication, a real upstream |
| `tests.test_link_producers` | An AST inventory of every `mask*.py` call that creates a link or computes a link text, and of every `mask_pinned.target` derivation, matches its allowlist. After public link producers run on a tap-first machine, every recorded and observed owned link is under `MASK_HOME/store/v1`, except the explicit `source dev-link`. A mode-less record refuses every planner entry and writes nothing | A link spelling outside the scanned call names, host discovery of the linked skill |
| `tests.test_retired_paths` | `capabilities` omits the retired commands, and invoking one is `invocation.invalid` with nothing written. On v1 and v2 machines every non-exempt command refuses `migration.required` before any effect. Constructed retired journals are shown by `recover --inspect` and refused `recovery.conflict`. Consumer refusals on a tap machine carry the doctor remediation | Journals left by a real crash of the previous program, legacy files other than the schema-true fixtures of `tests.legacy_support` |
| `tests.test_doctor_migration` | Cases M01-M10 and M12 on schema-true v1 and v2 fixtures. `doctor` reports and `--check` exits 7 without writing. `--migrate --dry-run` writes nothing, and its hash binds the apply. `--migrate` yields v3 config, v2 declarations and locks at the clone HEAD, the cache, store payloads and store links. A crash at every checkpoint rolls back to exact bytes and links or completes. An empty registry converts the configuration only. Typed refusals write nothing. The previous program refuses the journal; that case is skipped when revision `b92372f` is absent | The owner's machine migration (MASK-0107), legacy states the fixtures do not model, power-loss durability |
| `tests.test_doctor_straggler` | Case M11 on a tap machine: an unregistered v1 project or personal declaration, or a registered mode-less record, converts through `doctor --migrate --project PATH --alias NAME` (or `--user --alias NAME`). It uses install semantics in one `doctor.migrate` journal without a `migration` field. A crash at every checkpoint rolls back or completes. A tampered after selection refuses recovery, and invalid invocation, alias, declaration or pending states refuse without writing | Stragglers other than v1 declarations and mode-less records, a network remote |
| `tests.test_tap_line_endings` | Under a disposable global `core.autocrlf=true`, an exact tap publishes exact bytes and refuses a converted clone before any effect. An `--autocrlf` tap records and discloses the conversion and matches the blobs Git itself stores. Committed line-ending attributes refuse. An entry without `line_endings` keeps exact bytes. `doctor --migrate` writes `exact`. Capabilities, `tap add` help and the v3 schema describe the policy | Other Git line-ending or filter configurations, system Git configuration |
| `tests.test_retired_spellings` | Every help page renders without a retired command spelling. Public `--help`, `update --help`, `doctor --help` and `capabilities` agree with the command table. Current Markdown names no retired spelling outside historical records and the migration guide's old-command table, and that table maps each one | That the documentation is otherwise accurate, retired spellings the pattern does not match |

Use `python -m unittest <module>` on the selected interpreter. All fixture roots, fake remotes and MASK_HOME values must be private temporary locations. Preserve/review the root before cleanup; test fixture cleanup is allowed for test-owned temporary directories, but MASK runtime never recursively deletes user paths.

Windows and macOS native cards select only symlink/launcher tests and the one end-to-end path relevant to the claim. Do not multiply every Python version by every OS by every host/runtime. Linux results may support portable logic but do not satisfy native cards. Optional real-agent discovery must name the actual host/version and whether an enabled skill was observed; missing credentials or a runtime not present is not a product test pass.

No broad soak, repeated unchanged clean build, large evidence archive or model evaluation framework is requested. Record focused command/result/commit on the live card and reuse unchanged results.
