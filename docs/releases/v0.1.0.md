# MASK v0.1.0 — local readiness, 2026-09-05

Implemented the supplied MASK RFC pack across the two existing private repositories. All 18 MASK cards and 6 AgentSkills cards are completed at their stated acceptance boundaries. ## What is available

A standard-library Python CLI with versioned JSON/capabilities, strict declarations/configuration, passive skill inspection, explicit project registration, guarded reconciliation, exact symlink ownership, durable recovery/adoption/doctor, frozen fast-forward source updates, owned launchers and separate compatible program updates. The canonical direct entrypoint is `python /absolute/ManageAgentSkills/mask.py`. Use a known Python 3.11+ interpreter and installed Git; native verification used Python 3.14.7. No third-party runtime library is required.

`implement-rfc` was imported first with original seed provenance, then made consumer-context aware. `manage-agent-skills` was added second after CLI acceptance. Both are project scoped in the two named repositories, with Claude/Codex directory links to the same canonical payloads and distinct `.mask/skill-config/implement-rfc/` context. Current agent UI discovery/loading was not observed; native links and bounded shared-script invocation were directly verified.

The macOS installation uses `~/.local/bin/mask`, discoverable on the existing PATH, and `~/.mask` for machine state. No PATH edit was needed. The launcher records its selected actual interpreter; reinstall explicitly if that interpreter is removed by a package-manager upgrade. Both named repositories converge (`apply --all` no-op) and `doctor --all --check` reports healthy.

## Operating limits

Use README.md and the CLI contract for installation, preview/guard, update, recovery and unregister commands. MASK does not sandbox Git helpers/filters or defend against a malicious process racing filesystem operations. It checks cooperative edits immediately before bounded writes and preserves unexpected content. A single shared checkout offers no per-session atomic bundle activation; running agents may cache skills. Program schema migration requires explicit review, and there is no destructive Git rollback after source advancement.

There is one source, no per-project version pin, no global skill installation, daemon, fleet sync, marketplace, downloaded installer, automatic commit/push or public visibility change. New capabilities require new RFCs. Ordinary unregister removes only unchanged owned links and preserves declarations/context/source; explicit keep-links abandons ownership. Source/program/launcher removal is a separate scoped user action, not a purge feature.
