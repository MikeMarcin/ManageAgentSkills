# Useful implementation milestones

**M0 — Capture the defect, not a prepared happy path.** Import/reconcile live source
and add terminal-output and missing-role public regressions (MASK-0083).

**M1 — Readable immediately.** Add a human renderer for every current command,
readable errors, correct help/version, and format coverage (MASK-0084). This can
land before the rest; do not wait for optional setup execution to fix JSON spam.

**M2 — Finish a task in one command.** Add confirmation/authority handling
(MASK-0085), install/remove/list for both selection versions (MASK-0086), and
complete updates while preserving their real scope (MASK-0087). Native human
journeys and the short README land in MASK-0091, then close RFC-MASK-0018 in
MASK-0093. That closeout covers link/task behavior, not a missing future workflow
integration; its docs must state the capability actually shipped at that moment.

**M3 — Make dependencies ordinary artifacts.** Parse passive workflow metadata,
validate/deploy static roles, and recognize exact checked-in consumer roles
(MASK-0088). Share the typed ownership engine; do not run a generator for already
available outputs.

**M4 — Complete only genuinely necessary setup.** Add the bounded, consented,
staged script path (MASK-0089), then integrate the same prerequisite checks with
ensure/install/update/launch and receive the AgentSkills handoff (MASK-0090).
MASK-0092 exercises real shared-workflow and native end-to-end checks, then
MASK-0094 closes RFC-MASK-0019.

M2 and M3 can proceed independently after their shared prerequisites, but changes
to mask.py, the journal, adapter registry, and common tests require integrator
ownership scheduling. Do not turn twelve cards into twelve compulsory long-lived
agent sessions. Use coherent milestones, focused evidence, and compact handoffs.
The imported dependency graph, not this retained document, controls live work.
